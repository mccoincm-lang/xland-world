# Xland world — working rules

- This repo is the live xland.world. Every push to `main` is built and deployed by Cloudflare Workers Builds.
- Edit `src/`, then run `node tools/build.mjs` and commit `dist/index.html` with the change.
- Game rules, economy and the API must not change as a side effect of UI work. Before pushing, run the local server (`node test/dev-server.mjs`) and check `#/tests`: all rule tests must pass.
- The emblems and ornaments in `src/sprite.svg` are hand-drawn and approved by the founder. Regenerate only with `tools/build-sprite.sh`; never redraw them.
- `wrangler.toml` has no routes on purpose: the xland.world domain and the `ADMIN_KEY` secret live in the Cloudflare dashboard.
- The House on the River (Aquax, parcel AQX-01) is the founder's: keep it tiny and unobtrusive. It is eternal: no code may ever sell, transfer, tax, divide or reassign it, and the server refuses any claim on it.
- Founder decisions on population (21,000,000 in five stages, shares per territory, Xasteland at 90% of open homes), shop costs per territory and the QuarX daily sale limit live in `POP`, `SHOP_TERR` (index.html) and `SHOPS` (worker.js). Change them only on the founder's word.
- Since r52 the server holds every citizen's official wallet (`xl_wallets`, `xl_ledger` in worker.js). The page only proposes operations through its outbox; value may enter a wallet only through `walletPropose` rules or a server endpoint that credits it (seams, harvests, the order book, the sandbox mint). Any new feature that gives citizens value must add its server rule, or the server will refuse it and the page will be aligned back.
- Since r53 construction and the shared Assembly are server rules: a build site is opened, committed, cancelled and completed only through `/api/build/*` (the page's `proj-` and `build-` wallet operations are refused), and proposals, ballots, quorum, windows and the law set live in `xl_proposals`/`xl_ballots` (`/api/gov*`). The page mirrors them (`srvBuild`, `govSync`). Residency for the Assembly is verified by the server (a home paid for or a parcel claimed), not by the citizen's self-reported identity.
- Since r54 (founder decisions of 25 Oct 2026): mining difficulty targets `ECON.targetSeamsPerDay` (256,673 seams a day across Xland), not a number of miners; QuarX costs of shopfronts and buildings are multiples of the current seam reward (`quarxCost`/`shopCost` in worker.js, `quarxCostU`/`shopCostU` in index.html), so they halve with each halving. The server also enforces that shops list only produced stock (`listableQty`), that presale QuarX is untradable for 12 months (`vestedQuarx`), and computes the Xahara anti-flip fee itself from the acquisition date. `test/wallet-attacks.cjs` must show 0 failures before a push.
- Since r55 (living map): land is bought only through `/api/land/buy`, which claims and charges in one server step; a claim written through `/api/doc` is refused unless already paid, and page-made `parcel-` and `repair-` wallet operations are refused. The lots, their prices and what may be built on each live in `src/world.json`, shared by the page (inlined by `tools/build.mjs`) and the Worker. A citizen may hold 3 lots per territory (`LOT_CAP`, `SIM.lotCapPerTerritory`). Building condition is computed by the server (`buildCond`): slow wear plus the damage of each hazard that began after the building was finished or repaired; repairs go through `/api/build/repair`. Hazards come from real weather at each territory's twin on Earth (hourly cron, `weatherBridge`) or from the founder (`/api/hazard/raise`). `test/living-map.cjs` must pass with `wallet-attacks.cjs`.
- Since r56 (land between citizens): a holder lists land with `/api/land/list` (whole BuX, never below the resale floor in Ximberland and Tundrax, nothing building on it) and withdraws with `/api/land/unlist`; another citizen buys through `/api/land/buy?parcel=&price=`, which takes the listing (so it sells once), charges the buyer, moves the claim and every finished building on it, and pays the seller less the anti-flip fee (`FLIP`, from the server's own record of when the seller acquired it, `xl_landbasis`). Listings are public in `/api/world` (`living.listings`). Page-made `land-` wallet operations are refused.
- Since r57 (tokens on Base): `/forge` serves the founder's Forge page (`src/forge.html`, with `src/forge-core.cjs`, vendored ethers 6.13.4 and the compiled contracts inlined by `tools/build.mjs`). It only builds transactions for the visitor's own wallet to sign; it never sees a key and calls nothing on this server. It creates QuarX, BuX and Lex as B20 tokens (supply zero, QuarX capped at 1,000,000,000, BuX limited to the citizens allowlist and paused, Lex non-transferable) and deploys `contracts/src/XlandDeeds.sol` (moved only by the land office; AQX-01 can never be minted) and `XlandPassport.sol` (soulbound). Never ask for or accept a private key or recovery phrase. Contract changes need `tools/contracts-test.sh` to pass and `contracts/out/xland-contracts.json` regenerated from that build.
- Since r58 (weather you can see, bracing, and the review fixes): the page may reserve (`kind:'lock'`) only for its shop and market listings (`PAGE_LOCK_PREFIXES`); a payment counts only if the ledger row really paid the price (`paidOp`), never because an operation of that name exists; a claim through `/api/doc` is only a holder rewriting their own claim, a parcel paid in full, or one Ximberland home for a full-price Homax. Repairs and braces take the building first and charge second (one of several requests at once wins). `/api/build/brace` halves the damage of hazards that begin in the next 24 hours for a tenth of the recipe value; the weather bridge also stores the next twelve hours' first hazard as a forecast. Requests at the same moment are tested by `test/races.cjs` on `XLAND_SLOW=1 node test/dev-server.mjs 8790`; it must pass with `wallet-attacks.cjs` and `living-map.cjs` before a push. The app icons in `src/icons.json` come from `tools/build-icons.cjs`.
- Since r59 (arrival and first session, CX pass): the lore intro is never shown by itself (only from "Watch the story"); Hotex is three steps (name, optional interests, passport) and the old `hx-next` reading steps are gone, so tests go straight to `#hx-handle`; a new passport starts the first-steps guide as a small pill on phones and a slim line on wide screens; the passport page keeps its secondary cards behind "Show the full record" (`ui.ppMore`). In sentences shown to citizens say "not decided yet" rather than "TBD in the canon", and never show template or version strings; the CANON / SIMULATION / TBD status tags themselves stay.
